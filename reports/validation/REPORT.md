# 模型与本地研读验证

测量日期：2026-11-13。设备为 RTX 4060 Laptop 8GB；默认模型 `clean_2k_seed24`，原生 CUDA Q8，阅读断句使用输入原文约束。这里只汇总当前可用方案的证据，不把程序验收当作模型语义质量。

## 原文约束断句

相同微调 Q8 在生成前冻结的 40 条保留断句题上比较自由/约束生成，bench 与 ood 各 20 条。使用相同模板、greedy、seed24、512 输出 token 上限，并关闭 prompt cache；已核对原生与 HF tokenizer 的输入 token。题目来自已有来源语料，参考只做结构和输入资格筛查，没有逐题专家校点认证。

|题组|自由严格边界 F1|约束严格边界 F1|约束完整正文一致率|
|---|---:|---:|---:|
|bench|0.6829|0.8291|1.0000|
|ood|0.8172|0.9094|1.0000|
|全部样本均值|0.7501|0.8693|1.0000|

同题配对均值差为 +0.1192，样本 bootstrap 95% 区间约 [0.0253, 0.2141]。区间只反映当前题集重采样，不覆盖训练种子和典籍选择变异。每组生成前的门槛为 F1 下降不超过 0.01、完整正文一致率至少 0.98，均通过；题目已经评分，后续不再当作未见测试。

这是**解码策略对照**，不是基座到微调的收益。严格边界 F1 在正文变化时归零，否则比较标点位置，不代表标点类型或语义完全正确。正文一致是解码契约，不能当作学习出的语义能力。

可核对文件：[冻结身份](holdout-selection.json)、[汇总](clean-q8-heldout.json)、[自由输出](clean-q8-heldout-free-samples.jsonl)、[约束输出](clean-q8-heldout-constrained-samples.jsonl)。

## 开发基线与量化对照

开发题已经用于方案诊断，不是未见测试。两示例基座从训练集按长度确定性选择不同典籍的示例，身份和完整提示固定保存。

|模型/提示|自由严格 F1|约束严格 F1|
|---|---:|---:|
|基座 Q8，零示例|0.2694|0.3552|
|基座 Q8，两示例|0.6477|0.8973|
|微调 Q8，零示例|0.8295|0.9177|
|微调 Q4，零示例|0.7955|0.9107|

强提示基线显著缩小了差距。微调 Q8 约束与两示例基座 Q8 约束的差值约 +0.0204，样本区间约 [0.0046, 0.0373]；提示词不同，因此属于实用方案比较，不能解释为纯训练因果效应。

Q8/Q4 来自同一合并 checkpoint，当前默认 Q8。数据只支持所测断句范围，不能推导 Q4 全任务质量损失低于 1%。HF NF4 与原生 GGUF 属于不同后端协议，不能混在同一量化消融里。

详见 [基座零示例](base-q8-dev.json)、[基座两示例](base-q8-two-shot.json)、[微调 Q8](clean-q8-dev.json)、[微调 Q4](clean-q4-dev.json) 和相邻样本 JSONL。

## 训练控制

正式微调对同一冻结数据运行 seed24、seed42；LoRA 初始化前设定种子，仅按开发损失选 checkpoint，默认 seed24 不依据测试分数替换。两次重复只能初步观察波动，不证明稳定饱和或无遗忘。

训练使用 r=32、alpha=64，适配七类投影，NF4 + double quant、BF16 计算、batch=1、梯度累积=8、梯度检查点和约 5% warmup。提示标签为 -100，只监督答案；超长数据不静默截断。按典籍分范围，并检查测试输入/答案与训练内容的精确及近重复。

现有默认训练语料存在已确认的语义配对问题；后续审核候选未通过发布检查，没有替换当前权重。公开分数是给定参考下的自动指标，独立人类翻译盲评仍未完成。翻译 chrF、断句 F1 和工程检查不作异质平均。

双种子结果见 [训练对照](training-comparison.json)、[两种子说明](SEED_COMPARISON.md)、[seed24 训练记录](train-clean_2k_seed24.json)、[seed42 训练记录](train-clean_2k_seed42.json)。训练对照为从原始报告选取当前控制组，未重算或更改指标；三组样本输出随附。

## 本机性能

长文为来源语料自然段，三种长度各一次，包含网关、分段、实际生成和保存；不是未见语义质量测试或 P95。

|原文字符|分段数|完整处理秒数|新增输出 token|完整且正文一致|
|---:|---:|---:|---:|---|
|500|3|12.83|603|是|
|1500|9|34.96|1704|是|
|3000|17|69.55|3399|是|

通用聊天 SSE 短请求测试预热模型，重复四类提示，输出上限 128 token，不启用阅读约束：

|并发提交|请求数|成功数|TTFT P95 ms|端到端 P95 ms|
|---:|---:|---:|---:|---:|
|1|30|30|65.5|515.4|
|2|30|30|533.2|845.6|

实际模型生成并发仍为 1。上述负载和样本有限，不代表长文延迟、纯解码吞吐或生产 SLA。详细数据见 [长文记录](document-benchmark.json)、[短请求记录](gateway-benchmark.json)。
